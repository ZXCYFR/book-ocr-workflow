# 从扫描专著到清晰排印：ZCode 与 GPT 的协作流程

这份资料记录一个扫描书籍数字化项目：将1940年的俄文水螨分类学专著，从268张扫描整理为535页清晰、可搜索的电子排印PDF。文字用电子字体重排，保留原分页和原物理换行；285处插图来自扫描裁剪，并在最终阶段完成高清增强。

**这是方法与流程资料包，不是可安装运行的OCR软件，也不包含原书、字体、模型权重或内部会话记录。**

## 项目为何比预期困难

初始OCR表现较好。在6张扫描页的12个区域、36行、1,912个参考字符上，Surya OCR 2取得0.94%的内容字符错误率；Qwen3.5-2B和PaddleOCR-VL-1.6用作交叉候选。这个小样结果不代表整书错误率，也不评价空格、换行和版式。

最初把OCR嵌入原扫描PDF，只解决了搜索和复制：读者看到的仍是模糊的扫描字迹。项目随后转向电子字体重排。主要难点变成了确认正确文字、找出遗漏、修复疑难和保持图文布局，而不是一次性识别。

项目低估了逐行校对和返修的成本。可靠的结果来自可编辑输入、脚本迭代、原图核对、分层复核和版本检查，不来自模型直接宣布“完成”。

## 主协作流程

以下模型分工依据项目负责人复盘归纳，描述主工作流，而不是软件性能评测。

1. **ZCode＋GLM 5.3**搭建工作流和制作、修复、矫正脚本库，随真实错误迭代，负责规划与批次审核。
2. **ZCode＋GLM 5.3 Flash**承担主要逐页制作、自校与复核，定位并修订文字和版式问题。
3. **GPT 6.1 sol（中等推理强度）**负责全局独立复核及错误矫正。
4. **GPT 6 astra（中等推理强度）**处理剩余难点、上下文与原书表述核对，完成终局修复和最终审核。
5. 对已核对内容汇编，完成去斜、统一尺寸、清洁排印及插图高清增强，再检查交付版本。

复核的独立性体现在对原扫描和实际输出重新检查，而不只是模型名称不同。修改内容后必须检查新版本，不能套用旧版“通过”记录。

## 文字和插图采用不同处理原则

文字残缺时，在明确授权下结合词典、上下文、同书用例或对应原文献恢复可见文字及搜索文字。恢复需要证据并记录为编辑性补正，不冒称原笔画直接可见；多个合理读法不能靠猜测消除。

插图使用原扫描裁图，没有按文字描述重新生成整图或重绘缺失的解剖结构。最终采用RealESRNet_x4plus做四倍超分辨率增强，改善边缘和平滑度。增强会改变像素，不能解释为恢复了扫描中不存在的真实细节。

先处理281处批量页插图，随后补齐4处另列手工页插图，最终共285处图像对象。这个数字不是插图页数。补齐步骤验证535页文字、内容流、非图像资源和页面属性不变，其余281处图像字节不变，并检查4处图像及最终四页显示。历史全书校对与最终局部复验分开记录。


## 最终交付与文件体积

最终保留两份535页PDF：高清归档版289.75 MB，以及日常使用的1200 dpi黑白阅读版51.42 MB。两者保留同样的文字和页面绘制指令；285张插图在阅读版中按阈值180转为1位黑白，再以CCITT Group 4编码，体积较高清版缩小82.25%。

这个结果来自按线描图特征选择编码，而不是把白底改成透明。黑白图保留高像素尺寸，但去掉灰色过渡，会改变边缘；CCITT对二值结果无损，不表示灰度转黑白无损。原高清版和原扫描继续保留用于细节对照。

535页文字、内容流和页面尺寸逐页核对，285张二值图通过独立解码检查；另检查8张灰度敏感图的局部及3页整页。技术一致和抽查不代表全部细微形态绝对不变。详见[插图编码与压缩](COMPRESSION.md)。

## 最重要的选型经验

项目负责人认为，本次最大的教训是不能只按模型名称选择执行工具：即使标称调用同一GLM 5.3 Flash，不同工具入口下的任务完成度、速度和返修成本也可能明显不同。本项目的实际经验支持固定使用ZCode承接GLM制作与批次审核，再由GPT独立终审，减少跨工具切换与标准不一致。

这是单项目使用经验，不是控制了模型后端、提示词、上下文、工具权限与采样参数的性能实验；差异的具体原因尚未独立拆解。因此，复用时应先用真实小批次验收完整工具链，而不是假设同名模型的效果相同。

## 复用范围

适合复用的是稳定页面ID、可编辑逐行输入、原图对照、制作与验收分离、问题留痕、文件指纹及完整页序核对。模型、语言字典、字体、排版参数和页映射需要按新书重新验证。

这些材料不保证无残余错误，也不提供可直接处理任意书籍的流水线。需要可运行工具时，应另行准备可再分发示例、参数化路径、依赖环境与端到端测试。
